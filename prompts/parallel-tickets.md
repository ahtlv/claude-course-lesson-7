# Два тикета одновременно: параллельные агенты

**Когда:** на занятии 7 после перерыва, дома на оставшихся тикетах MVP.
**Что делает:** главный агент выбирает два независимых тикета, запускает на них двух
субагентов **одновременно**, каждого в своей изолированной копии проекта, а потом сливает
обе работы в одну.
**Как использовать:** открой папку `work/StartUp/landing`, новая сессия. Впиши номер карточки
спеки MVP и отправь.

> **Чем это отличается от занятия 4.** Там команда агентов шла друг за другом: один сделал,
> другой проверил, следующий взялся. Сегодня двое работают в одно время. Чтобы они не
> мешали друг другу, у каждого своя рабочая копия проекта (git worktree): отдельная папка
> со своей веткой. Один не видит черновиков другого, пока главный агент их не сольёт.

```text
Посмотри открытые тикеты в карточке спеки MVP #[номер спеки].

1. Выбери два тикета, которые можно делать одновременно: оба не заблокированы, не зависят
   друг от друга и по возможности меняют разные файлы. Скажи, какие и почему, и дождись
   моего «да».

2. Запусти двух субагентов одновременно, каждого в своей изолированной рабочей копии
   проекта (git worktree, у каждого своя ветка). Каждому дай задание:
   - прочитать свой тикет, карточку спеки и CLAUDE.md;
   - сделать тикет только на HTML, CSS и JavaScript, без npm, сборки и тестовых фреймворков;
   - закоммитить в свою ветку и вернуть короткий отчёт: что сделано, какие файлы менял.
   Субагенты ничего не пушат и тикеты не закрывают. Пока они работают, сам ничего не меняй.

3. Когда оба закончат, покажи мне два отчёта рядом.

4. Слей обе ветки в main по очереди. Если случится конфликт, объясни мне простыми словами,
   что с чем столкнулось, и разреши его так, чтобы сохранились оба изменения.

5. Открой страницу в браузере и скажи, что мне проверить руками по каждому тикету.

6. После моего «работает» запушь, закрой оба тикета на GitHub коротким комментарием и
   удали рабочие копии и их ветки.
```

## Что будет происходить

1. Агент предлагает пару тикетов. Если тикеты трогают одну и ту же часть страницы, попроси
   другую пару: «найди два, которые меняют разные файлы».
2. В окне видно двух субагентов, они работают одновременно. Это тот момент, когда можно
   встать за кофе.
3. Отчёты, слияние, проверка в браузере, push. Через минуту изменения на GitHub Pages.

## Если что-то не так

- **Агент делает тикеты сам, по очереди** → «Стоп. Запусти двух субагентов одновременно,
  каждого в своей рабочей копии через git worktree».
- **Конфликт при слиянии** не поломка, а нормальная часть работы. Пусть агент покажет, что
  было у каждого, и спросит тебя, если не уверен.
- **Лимит подписки закончился быстрее обычного.** Два агента расходуют лимит вдвое быстрее.
  На тарифе Pro держи не больше двух одновременно.
- **Открытых тикетов меньше двух** → сделай один обычным промптом
  [`first-ticket.md`](https://github.com/ahtlv/claude-course-lesson-5/blob/main/prompts/first-ticket.md),
  а параллельно запусти аудит безопасности по Persona.

# Хук: агент не трогает файлы с секретами

> Инструкция одинаковая для Windows, macOS и Linux: агент сам определяет систему и
> подбирает способ. На Windows терминал только `cmd`, если открылся PowerShell, переключись.

**Когда:** на занятии 7, в блоке безопасности. Ставим всей группой.
**Что делает:** ставит правило, по которому агент **не может** читать и менять файлы с
секретами: `.env`, ключи, сертификаты, служебную папку `.git/`. При попытке он получает отказ
с причиной и ищет другой путь.
**Как использовать:** отправь промпт как есть. Звуковой хук с занятия 6 останется на месте,
агент только допишет новый рядом.

> **Зачем это нужно.** Звуковой хук что-то **делал**. Этот **запрещает**. Правило в `CLAUDE.md`
> агент может забыть или обойти, а хук запускает сам Claude Code перед каждым действием, и
> модель его не отключит.

```text
Хочу поставить хук, который запрещает тебе читать и изменять мои файлы с секретами.

Работай по полным (абсолютным) путям и показывай мне результат каждого шага.

1. Определи мою операционную систему.

2. Проверь, чем можно выполнить проверку на моей машине, и скажи, что нашлось:
   - node --version   (он у меня должен быть с занятия 3, ставили для Playwright)
   - python3 --version
   Выбери то, что реально работает. Если не работает ничего, остановись и скажи мне.

3. Найди мой settings.json. Сначала посмотри, есть ли папка конфига claude-config рядом
   с моими проектами: если есть, работай с файлом внутри неё. Если нет, работай с системным:
   ~/.claude/settings.json на macOS/Linux, %USERPROFILE%\.claude\settings.json на Windows.

4. Рядом с settings.json, в подпапке hooks, создай скрипт-проверяльщик на языке из шага 2.
   Что он делает:
   - читает JSON, который передаёт Claude Code, и берёт из него путь к файлу
     (поле file_path внутри tool_input);
   - проверяет, попадает ли путь под запрет. Запрещаем:
       .env и все файлы, имя которых начинается с .env, КРОМЕ .env.example
       файлы с расширениями .pem, .key, .p12, .pfx
       всё внутри папки .git/
       файлы с именами id_rsa, id_ed25519, credentials, secrets.json
   - если попадает, печатает в поток ошибок понятную причину, например:
     «Файл .env защищён хуком: в нём лежат ключи. Если правда нужно, открой его сам
      в редакторе», и завершается с кодом 2 (сигнал «нельзя»);
   - если не попадает, завершается с кодом 0 (сигнал «можно»).
   Список запретов вынеси наверх скрипта отдельной строкой с комментарием по-русски,
   чтобы я мог дописывать туда свои файлы.

5. Пропиши хук в settings.json. Прочитай файл целиком и ДОПИШИ блок, ничего не затирая:
   ни model, ни permissions, ни хук со звуком на событие Stop. Нужен такой блок:

   "PreToolUse": [
     {
       "matcher": "Read|Write|Edit",
       "hooks": [
         { "type": "command", "command": "КОМАНДА_ЗАПУСКА_СКРИПТА_С_ПОЛНЫМ_ПУТЁМ" }
       ]
     }
   ]

   Путь пиши полный. Если в пути есть пробелы, позаботься о кавычках.

6. Проверь, что settings.json остался валидным JSON. Битый файл молча отключает ВСЕ
   настройки, включая звуковой хук. Если файл невалиден, верни исходное содержимое.

7. Проверь сам скрипт без Claude Code: передай ему на вход пример JSON с путём к .env
   и пример с путём к index.html. Покажи мне, что в первом случае код выхода 2,
   во втором 0.

8. Создай в текущей папке тестовый файл .env со строкой SECRET_KEY=test.

9. Покажи мне:
   - полный путь к скрипту и его содержимое;
   - только блок hooks из settings.json;
   - подтверждение, что звуковой хук на месте.

10. В конце скажи мне ровно эту фразу и больше ничего не запускай:
    «Перезапусти окно VS Code, открой новую сессию и попроси меня показать, что лежит
     в файле .env».
```

## Смотрим отказ вживую

Перезапусти окно VS Code, открой новую сессию и попроси:

```text
Покажи, что лежит в файле .env в этой папке.
```

Агент должен получить отказ с твоей причиной и сказать об этом. Это и есть момент занятия:
модель хотела, а правило не пустило. Потом попроси «допиши в .env строку TEST=1», отказ должен
быть и здесь.

Список хуков виден командой `/hooks`: теперь их два, звук на `Stop` и защита на `PreToolUse`.

Тестовый `.env` удали сам, руками в проводнике или Finder: он нам больше не нужен.

> ⚠️ **Хук это ремень безопасности, а не сейф.** Он ловит инструменты чтения и правки файлов.
> Агент, который очень захочет, может попробовать прочитать файл командой в терминале, и
> тогда хук этого не увидит. Главная защита остаётся прежней: секретов в папке со страницей
> нет вообще, а там, где они есть, `.env` лежит в `.gitignore`.

---

## Как добавить свои файлы под защиту

Открой скрипт, список запретов лежит наверху отдельной строкой. Допиши туда:

- конфиги с доступами: пароли к базам, ключи от сервисов;
- договоры и личные документы, если они лежат в папке проекта;
- файл, который агент однажды сломал и который ты правишь только руками.

Перезапускать ничего не надо: скрипт читается заново при каждом срабатывании.

## Если отказа нет

1. **Перезапустил окно VS Code?** Хуки подхватываются при старте.
2. **Что показывает `/hooks`?** Хука нет, значит он не прописался в `settings.json`.
3. **Пропал звук с занятия 6?** Почти наверняка `settings.json` стал невалидным: пропущена
   запятая между блоками. Попроси агента проверить синтаксис файла.
4. **Хук есть, а файл всё равно читается?** Проверь `matcher`: в нём должны быть `Read`,
   `Write` и `Edit`.
5. **Агент ушёл выполнять что-то в терминале после шага 10?** Останови его кнопкой стоп и
   скажи: «Ничего не запускай, просто дождись, пока я перезапущу VS Code».

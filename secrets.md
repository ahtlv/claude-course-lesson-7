# Секреты проекта: где они живут и почему у тебя их пока нет

## Что такое секрет

Секрет это строка, которая открывает дверь: ключ к сервису, токен бота, пароль от админки,
доступ к базе. У кого строка, тот и хозяин двери. Сервис не спрашивает, кто ты, он смотрит
только на ключ.

## Где секреты живут: файл `.env`

В настоящем проекте секреты лежат в отдельном файле `.env` в папке проекта. Выглядит это так:

```text
TELEGRAM_BOT_TOKEN=000000000:DEMO-not-a-real-token
OPENAI_API_KEY=demo-key-NOT-REAL
ADMIN_PASSWORD=demo-password-change-me
```

Имя слева, значение справа. Код проекта берёт значение по имени и никогда не держит его у себя
в тексте. Поэтому код можно показывать, выкладывать и отдавать агенту, а `.env` остаётся дома.

## Кто не пускает `.env` на GitHub: файл `.gitignore`

`.gitignore` это список «этого на GitHub не отправлять». Git читает его перед каждой отправкой
и молча пропускает всё, что там перечислено. Файл на компьютере остаётся, на GitHub не уезжает.

```text
# секреты
.env

# мусор системы
.DS_Store
```

Что обычно попадает в этот список:

- **секреты**: `.env` и всё, что начинается с `.env`;
- **мусор системы**: `.DS_Store` на macOS, `Thumbs.db` на Windows;
- **то, что создаётся само**: папки, которые собирает агент или программа, их всегда можно
  получить заново.

Посмотри живой пример: https://github.com/ahtlv/env-demo. На компьютере автора в этой папке
лежит `.env` с ключами, а на GitHub его нет. Зато там есть `.env.example`: тот же список имён,
но без значений. По нему видно, какие ключи нужны проекту, а сами ключи у владельца.

## Почему у тебя `.env` нет

Твои страницы живут на GitHub Pages. Это хостинг для готовых файлов: он просто отдаёт браузеру
HTML, CSS и JavaScript как есть. Своего сервера, который мог бы тайно держать ключ, у страницы
нет.

Отсюда главное правило: **всё, что лежит в файлах страницы, видит любой посетитель.** Правый
клик → «Просмотр кода страницы», и ключ перед глазами. Спрятать его в JavaScript, разбить на
части или зашифровать не поможет: браузер должен его прочитать, значит прочитает и человек.

Поэтому на статической странице секретов не бывает вообще. Если агент предлагает вставить
ключ прямо в код страницы, это сигнал остановиться и спросить, зачем.

`.env` появится, когда у проекта появится сервер: бот, форма с отправкой, своя база, VPS. Тогда
первым делом `.env` в `.gitignore`, и только потом первый ключ.

## Если ключ всё-таки уехал на GitHub

Удалить файл и отправить снова **не помогает**. Git помнит всю историю, и старая версия с
ключом остаётся в ней. Боты сканируют публичные репозитории постоянно и находят свежие ключи
за минуты.

Правильный порядок:

1. **Сначала отозвать ключ** в сервисе, который его выдал, и выпустить новый. С этой секунды
   утёкший ключ бесполезен.
2. Потом убрать файл из репозитория и добавить его в `.gitignore`.
3. Чистка истории это отдельная операция, её делают, только когда ключ уже отозван.

Отозвать важнее, чем спрятать.

## Агент и секреты

Claude Code читает файлы проекта, чтобы работать. Если в папке лежит `.env`, агент может
его открыть, и содержимое уйдёт в разговор с моделью. Поэтому на занятии мы ставим хук,
который запрещает агенту читать и менять файлы с секретами:
[`prompts/protect-secrets.md`](prompts/protect-secrets.md).
